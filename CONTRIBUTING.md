# Contributing

The repository begins as a public planning/foundation project.

Before external production-code contributions are accepted, Phase 0 must finalize:
- software license;
- CLA/DCO decision;
- code of conduct;
- security reporting channel;
- architecture and privacy contribution rules.

## Expected workflow

1. Open or reference an issue/ADR for material behavior changes.
2. Keep pull requests small and focused.
3. Add tests with behavior changes.
4. Update docs and threat model when a data flow changes.
5. Never commit real congregation/member data.
6. Never include secrets, production exports, screenshots with personal data or private correspondence.
7. Security-sensitive changes require dedicated review.

## Independence

Do not submit copied code, UI assets, logos, proprietary templates or reverse-engineered secrets from Hourglass, NW Scheduler, JW.ORG or other third-party products. Interoperability contributions must be clean-room and based on authorized user exports/public documentation.
